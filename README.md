# Beyond Money: Who Responds to Intergenerational Appeals for Sustainable Cooperation?

Analysis code for an MSc Business Analytics dissertation examining **who** responds to
intergenerational appeals in a common-pool-resource (CPR) game — extending the
treatment-effect findings of Testori & Lo Iacono (*European Sociological Review*) with a
moderation analysis of political ideology, legacy concern, and environmental concern.

The dissertation uses secondary data from the parent study's two pre-registered
experiments (MTurk and Prolific). This repository contains the full, reproducible analysis
pipeline; the underlying participant-level data is **not** included (see
[Data](#data-availability)).

---

## Research question and hypotheses

The parent study establishes *that* intergenerational awareness raises sustainable
("green") choice behaviour. This dissertation asks *for whom* that effect is strongest,
testing four hypotheses on the round-level probability of choosing the green option:

| # | Hypothesis |
|---|------------|
| **H1** | Liberal participants choose the green option more often than conservative participants, independently of treatment condition. |
| **H2** | The positive effect of intergenerational awareness on green choice is stronger for liberal than for conservative participants, relative to participants who received no intergenerational awareness. |
| **H3** | As H2, moderated by **legacy concern** (Prolific only). |
| **H4** | As H2, moderated by **environmental concern** (Prolific only). |

The experiment is a 2×2 between-subjects design with four conditions: **IT&GI**
(intergenerational + green information), **IT** (intergenerational only), **GI** (green
information only), and **NIT&NGI** (pure control, the reference category throughout).

---

## Method

The outcome (`extract_green_choice`) is binary at the round level, and the data are nested:
decision rounds within participants within experimental sessions. Following the parent
paper, models are **multilevel linear probability models** estimated by **REML**, with
random intercepts for sessions and participants.

The random-effects structure places **sessions at the top level**
(`groups='sessioncode'`) with a participant-level random intercept nested within
(`vc_formula={'participant': '0 + C(participantcode)'}`). This mirrors the parent paper's
stated specification — *round-decisions nested in individuals nested in sessions*, with the
session as the highest level of the hierarchy — and its Stata replication code
(`mixed ... || sessioncode: || participantcode:`). Sessions are the unit at which treatment
is randomised, so this is the level at which clustering must be modelled.

Treatment enters as a four-level factor referenced against the control condition, so each
contrast is interpretable on its own terms. The `IT`-only contrast is the primary test of
each moderation hypothesis, as it isolates intergenerational awareness from the
green-information framing.

Each hypothesis is estimated as a lean **primary** specification and a **robustness check**
adding the full pre-treatment covariate set; H4 additionally carries a climate-belief
robustness check. Because the moderators are measured individual differences rather than
randomised, the covariate-adjusted checks guard against demographic confounding of the
moderator terms.

### Notebook pipeline

The notebooks run in order; each depends on the cleaned files written by Notebook 01.

1. **01 — Data preparation.** Loads the raw decision-level exports, applies pre-registered
   exclusions (incomplete sessions; missing ideology), fixes the analytic sample by listwise
   deletion *before* any derived quantity is computed, then builds composites
   (legacy concern, environmental concern) and z-standardised moderators/controls on that
   fixed sample. Exports `mturk_clean.csv`, `prolific_clean.csv`, and a three-stage
   missingness audit.
2. **02 — Descriptive statistics.** Sample composition (Table 1), treatment allocation and
   randomisation balance (Table 2), the outcome variable by treatment (Table 3), moderator
   distributions, and the multilevel data structure.
3. **03 — H1.** Ideology main effect: primary and full-covariate specifications, with a
   side-by-side sensitivity comparison.
4. **04 — H2–H4.** Moderation models, each with primary and robustness specifications; H4
   adds a climate-belief robustness check.
5. **05 — R1–R3.** Robustness to alternative operationalisations of political orientation
   (continuous party ID; 2020 and 2024 vote choice).
6. **06 — Parent-paper replication.** Reproduces the parent study's treatment-effect
   analyses (round-level extraction choices and the session-level sustainability threshold)
   as a foundational check that the base effects this dissertation builds on hold in-sample.

## Reproducing the analysis

```bash
# 1. Environment
python -m venv .venv
source .venv/bin/activate          # Windows: .venv\Scripts\activate
pip install -r requirements.txt

# 2. Place the data files (not distributed here) in ./data/
#    - Data_decisions_MA_Mturk.csv
#    - Data_decisions_MA_Prolific.csv
#    - Data_sess-1.csv        (MTurk session-level, for Notebook 06)
#    - Data_sess-2.csv        (Prolific session-level, for Notebook 06)

# 3. Run the notebooks in order (01 → 06)
jupyter notebook
```

Notebook 01 must be run first: it writes the cleaned CSVs that every other notebook loads.
Outputs (tables, figures, model summaries) are written under `outputs/` as each notebook
runs.

## Data availability

The participant-level experimental data is **not** included in this repository and is
excluded via `.gitignore`. It originates from the parent study; access is governed by that
study's terms. The analytic sample comprises **1,022 MTurk** and **1,017 Prolific**
participants (10 decision rounds each) after pre-registered exclusions and listwise
deletion. To reproduce the results, obtain the raw data through the appropriate channel and
place the files in `data/` as listed above.

## Notes on specification choices

- **REML vs. ML.** Estimation uses REML; the parent
  paper reports maximum likelihood. This is a defensible difference for variance-component
  estimation rather than an error, and is noted here for transparency.
- **Optimiser.** Model fitting uses a sequential optimiser fallback
  (`['lbfgs', 'bfgs', 'cg', 'powell', 'nm']`); statsmodels tries each in turn and stops at
  the first that converges, with an explicit warning if none do.
- **Education** is treated as a single ordinal/categorical variable read from the
  `education` field; the raw `Edu_*` dummy columns were found inconsistent with it and are
  dropped in preparation.
- **`voted_trump_2020`** codes non-voters as missing *by design* (not incidental
  missingness); those cases are dropped only within the specific robustness run that uses
  the variable.
